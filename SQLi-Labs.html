Lab 01: SQL injection vulnerability in WHERE clause allowing retrieval of hidden data

Descripción del laboratorio

Este laboratorio contiene una vulnerabilidad de inyeccion de SQL en el filtro de categoria de productos. Cuando el usuario selecciona una categoría, la aplicación ejecuta una consulta SQL como la siguiente:

SELECT * FROM products WHERE category = 'Gifts' AND released = 1

Para resolver el laboratorio, se debe realizar un ataque de inyección SQL que haga que la aplicación muestre uno o más productos no lanzados.

Tipo de vulnerabilidaad: SQL Injection basada en manipulación lógica (Boolean-Based SQL Injection) en la cláusula WHERE.

Solucion del laboratorio

Los siguientes pasos fueron necesarios para la realizacion de este laboratorio

  1. Con Burpsuite, interceptar y modificar la solicitud que establece el filtro de categoría de producto.
  2. Modificar el parámetro de categoría, dándole el valor '+OR+1=1--'.
  3. Enviar la solicitud y verificar que la respuesta ahora contenga uno o más productos no publicados.

Lab 03: SQL injection attack, querying the database type and version on Oracle

Descripción del laboratorio

Este laboratorio contiene una vulnerabilidad de inyección SQL en el filtro de categoría de producto. Puede utilizar un ataque de UNIÓN para recuperar los resultados de una consulta inyectada.
Para resolver el laboratorio, muestre la cadena de versiones de la base de datos.
En las bases de datos de Oracle, cada SELECT La declaración debe especificar una tabla para seleccionar FROM. Si su ataque UNION SELECT no consulta desde una tabla, aún es necesario incluir el FROM seguido de un nombre de tabla válido. Hay una tabla incorporada en Oracle llamada dual que puede ser usada para este propósito.
Por ejemplo: UNION SELECT 'abc' FROM dual

Tipo de vulnerabilidad: UNION-based SQL Injection

Solucion del laboratorio

Los siguientes pasos fueron necesarios para la realizacion de este laboratorio

  1. Con Burpsuite, interceptar y modificar la solicitud que establece el filtro de categoría de producto.
  2. Determine el número de columnas que están siendo devueltas por la consulta y qué columnas contienen datos de texto. Verifique que la consulta devuelve dos columnas, ambas de las cuales contienen texto, utilizando una carga útil como category el siguiente parametro:
    '+UNION+SELECT+'abc','def'+FROM+dual--.
  3. Utilice la siguiente carga útil para mostrar la versión de la base de datos:
    '+UNION+SELECT+BANNER,+NULL+FROM+v$version--

Tipo de vulnerabilidaad: Union-based SQL Injection (In-band / Clásico).

Solucion del laboratorio

Los siguientes pasos fueron necesarios para la realizacion de este laboratorio

  1. Utilice Burp Suite para interceptar y modificar la solicitud que establece el filtro de categoría de producto.
  2. Determine el número de columnas que están siendo devueltas por la consulta y qué columnas contienen datos de texto. Verifique que la consulta devuelve dos columnas, ambas de las cuales contienen texto, utilizando una carga útil como la siguiente en el parámetro category:

Lab 11: Blind SQL injection with conditional responses

Descripción del laboratorio

Este laboratorio contiene una vulnerabilidad de inyección SQL ciega. La aplicación utiliza una cookie de seguimiento para análisis, y realiza una consulta SQL que contiene el valor de la cookie enviada.
Los resultados de la consulta SQL no se devuelven y no se muestran mensajes de error. Pero la aplicación incluye un mensaje de Welcome Back! en la página si la consulta devuelve alguna fila.
La base de datos contiene una tabla diferente llamada users, con columnas llamadas username y password. Debe explotar la vulnerabilidad de inyección SQL ciega para averiguar la contraseña del usuario administrator.
Para resolver el laboratorio, inicie sesión como el usuario administrator

Tipo de vulnerabilidaad: Fuerza bruta

Solucion del laboratorio

Los siguientes pasos fueron necesarios para la realizacion de este laboratorio

  1. Visite la página principal de la tienda y utilice Burp Suite para interceptar y modificar la solicitud que contiene la cookie TrackingId. Para simplificar, digamos que el valor original de la cookie es TrackingId=xyz.
  2. Modificar la cookie TrackingId, cambiandola a:
    TrackingId=xyz' AND '1'='1
    Debemos verificar que el mensaje de Welcome Back! aparezca en la respuesta.
  3. Ahora la cambiamos a:
    TrackingId=xyz' AND '1'='2
  4. La cambiamos a:
    TrackingId=xyz' AND (SELECT 'a' FROM users LIMIT 1)='a
  5. Ahora a:
    TrackingId=xyz' AND (SELECT 'a' FROM users WHERE username='administrator')='a
  6. Ahora debemos determinar cuantos caracteres hay en la contrase;a del amdinistrador para esto cambiamos el valor de la cookie a
    TrackingId=xyz' AND (SELECT 'a' FROM users WHERE username='administrator' AND LENGTH(password)>1)='a
  7. Envíe una serie de valores de seguimiento para probar diferentes longitudes de contraseña e ir aumentandolas hasta que desaparezca el mensaje de Welcome Back:
    TrackingId=xyz' AND (SELECT 'a' FROM users WHERE username='administrator' AND LENGTH(password)>3)='a
  8. Después de determinar la longitud de la contraseña, el siguiente paso es probar el carácter en cada posición para determinar su valor. Esto implica un número mucho mayor de solicitudes, por lo que debe usar Burp Intruder. Envíe la solicitud en la que está trabajando a Burp Intruder, utilizando el menú contextual.
  9. En el intruder cambiamos el valor de la cookie a:
    TrackingId=xyz' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='administrator')='a
    Esto utiliza la funcion SUBSTRING() para extraer un solo carácter de la contraseña y probarlo contra un valor específico. Nuestro ataque recorrerá cada posición y posible valor, probando cada uno a su vez.
  10. Coloque los marcadores de posición de carga útil alrededor de la final aEl carácter en el valor de la cookie. Para hacer esto, seleccione solo el a, y haga clic en el botón Añadir §. A continuación, debería ver lo siguiente como el valor de la cookie (tenga en cuenta los marcadores de posición de carga útil):
    TrackingId=xyz' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='administrator')='§a§
  11. Para probar el personaje en cada posición, deberás enviar cargas útiles adecuadas en la posición de carga útil que hayas definido. Puede suponer que la contraseña contiene solo caracteres alfanuméricos minúsculos. En el Panel lateral de cargas útiles, compruebe que la lista simple está seleccionada y debajo La configuración de carga útil añade las cargas útiles en el rango a - z y 0 - 9. Puede seleccionar estos fácilmente usando el menú desplegable Agregar desde la lista.
  12. Para poder saber cuándo se envió el carácter correcto, deberás aprovechar cada respuesta para la expresión Welcome back. Para hacer esto, haga clic en el Ficha para abrir el panel lateral Configuración. En la sección Grep - Match, borre las entradas existentes en la lista y, a continuación, agregue el valor Welcome back.
  13. Inicie el ataque haciendo clic en el botón Iniciar ataque.
  14. Revise los resultados del ataque para encontrar el valor del personaje en la primera posición. Deberías ver una columna en los resultados llamados Welcome back. Una de las filas debe tener una garrapata en esta columna. La carga útil que se muestra para esa fila es el valor del personaje en la primera posición.
  15. Ahora, simplemente necesita volver a ejecutar el ataque para cada una de las otras posiciones de caracteres en la contraseña, para determinar su valor. Para hacer esto, vuelva a la pestaña Intruder y cambie el desplazamiento especificado de 1 a 2. A continuación, debería ver lo siguiente como el valor de la cookie:
    TrackingId=xyz' AND (SELECT SUBSTRING(password,2,1) FROM users WHERE username='administrator')='a
  16. Inicie el ataque modificado, revise los resultados y anote el carácter en el segundo desplazamiento.
  17. Continúe este proceso probando el desplazamiento 3, 4, y así sucesivamente, hasta que tenga toda la contraseña.
  18. En el navegador, haga clic en Mi cuenta para abrir la página de inicio de sesión. Utilice la contraseña para iniciar sesión como el usuario administrator.
